# 📅 Day 03 – Requirement Engineering

# 🎯 Today's Goal

Understand **Requirement Engineering**, why it is important, its phases, and how software engineers gather and manage client requirements before development begins.

---

# 🤔 Why Do We Need Requirement Engineering?

Imagine a client tells you:

> **"I want a School Management App."**

If you immediately start coding, many questions remain unanswered:

* Who will use the app?
* Students, Teachers, Parents, or Principal?
* What features are required?
* Should it work offline?
* Should it support notifications?
* How will users log in?

Without understanding these details, there is a high chance of building the wrong software.

Requirement Engineering helps developers understand exactly what the client needs before writing any code.

---

# 📖 What is Requirement Engineering?

**Requirement Engineering (RE)** is the process of collecting, analyzing, documenting, validating, and managing the requirements of a software project.

In simple words,

> **Requirement Engineering is the process of understanding the client's needs before building the software.**

A successful software project always starts with clear requirements.

---

# 🏗️ Real-Life Analogy

Imagine a doctor treating a patient.

The doctor does not immediately prescribe medicine.

Instead, the doctor asks questions:

* What is the problem?
* Since when?
* Any previous medical history?
* Any allergies?

Only after understanding the problem does the doctor begin treatment.

Similarly, a Software Engineer first understands the client's problem before developing the solution.

---

# 📌 Phase 1 – Requirement Gathering

This is the first phase of Requirement Engineering.

The software engineer communicates with the client to collect information about the project.

Typical questions include:

* What problem should the software solve?
* Who are the target users?
* Which features are required?
* What is the expected deadline?
* What is the budget?
* Which platform should be supported?

### Example

For a School Management App:

* Student Login
* Teacher Login
* Attendance
* Homework
* Fee Management
* Results
* Notifications

The goal of this phase is to understand the client's expectations.

---

# 📌 Phase 2 – Requirement Analysis

After gathering information, developers analyze the collected requirements.

Questions asked during analysis include:

* Are all requirements clear?
* Is every feature technically possible?
* Which features are high priority?
* Are any requirements conflicting?
* Are any important requirements missing?

This phase helps identify potential problems before development begins.

---

# 📌 Phase 3 – Requirement Documentation

After analysis, all requirements are documented clearly.

Documentation ensures that everyone on the team has the same understanding of the project.

### Example

**Feature:** Student Login

**Description:**

Students should be able to log in using their enrollment number and password.

Good documentation reduces confusion during development.

---

# 📌 Phase 4 – Requirement Validation

The documented requirements are reviewed with the client.

The purpose is to confirm that the development team has correctly understood the project.

Questions asked include:

* Is anything missing?
* Is any feature incorrect?
* Should anything be modified?

Only after client approval does the project move forward.

---

# 📌 Phase 5 – Requirement Management

Software projects continue to evolve.

Clients often request new features or changes during development.

Example:

Initially:

* Attendance System

Later:

* QR Attendance
* Face Recognition
* Attendance Analytics

Requirement Management ensures that these changes are tracked and managed properly without creating confusion.

---

# 🌍 Real-World Example

Suppose you are building a **School Management App**.

## Poor Requirement

> "Add Attendance."

This statement is incomplete.

## Better Requirement

* Teachers can mark attendance.
* Students cannot edit attendance.
* Attendance is stored date-wise.
* Monthly reports can be generated.
* Parents can view attendance records.

This level of detail makes development much easier.

# ⭐ Advantages of Requirement Engineering

* Better understanding of the project
* Fewer misunderstandings
* Reduced development cost
* Less rework
* Better communication
* Higher customer satisfaction
* Improved software quality

---

# 💡 Best Practices

* Listen carefully to the client.
* Never assume missing details.
* Ask clear and relevant questions.
* Document every important requirement.
* Confirm requirements before development.
* Track future requirement changes.

---

# ⚠️ Common Beginner Mistakes

* Starting development without understanding requirements.
* Assuming features without asking the client.
* Ignoring documentation.
* Not confirming requirements with the client.
* Forgetting to manage future changes.

# 📝 Key Takeaways

* Requirement Engineering is one of the most important phases of Software Engineering.
* Clear requirements lead to successful software projects.
* Good documentation improves communication.
* Requirement changes must be managed throughout the project.
